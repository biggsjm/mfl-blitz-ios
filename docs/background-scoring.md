## Flow and limits

1. The native app starts only its verified current-week owner matchup while a reported starter is playing. A push-capable build requests an ActivityKit update token and registers it over the private Tailscale HTTPS service. Older local activities are replaced when push support is enabled.
2. The service reads only the configured public MFL `liveScoring` endpoint, grouping subscriptions by season/league/week. Champion Hall's Week 1 export was verified reachable from Hephaestus without a cookie or API key. The client cannot supply an arbitrary upstream URL.
3. One successful poll approximately every 60 seconds per subscribed league/week (build 55 onward) produces a priority-5 ActivityKit push, even if totals are unchanged, so the displayed check time stays meaningful. APNs delivery is best effort; a 210-second stale date makes missed updates visible. There is no iOS timer or silent notification pretending to provide continuous background execution.
4. Official franchise totals determine displayed scores and deltas. Starter attribution requires complete unchanged starter sets whose deltas reconcile to the official total. Otherwise the update names the team; simultaneous changes show both teams. The timestamp is an observation time, never a guessed play time. Failed reads never advance the displayed check time. Missing scores, ambiguous matchups and wrong weeks fail closed.
5. Reported starter clocks determine playing count. Both native and server updates retain an existing activity between games. Missing matchup totals or uncertain starter clocks preserve its last content instead of ending it. Explicit completion requires two fresh complete reads at least 60 seconds apart, known finished starters matching the expected lineup and consistent remaining-player counts; the final score remains for 15 minutes. Initial activity creation still requires an actively playing starter. No automatic push-to-start is implemented; open Blitz to start another activity. Settings → Game day includes the observed activity status and an explicit Restart Live Activity control, which clears a saved dismissal and requests fresh current-week scores before restarting.
6. The service stores at most eight subscriptions. Each expires 7h50m after its first registration; foreground renewals cannot extend it. APNs 410 removes it. Network/MFL errors back off up to 15 minutes; push configuration errors pause delivery. No upstream calls occur while the APNs key is absent. Poll reservations persist across restarts.

Live estimates use the same rule on the phone and server: official team points plus each unfinished starter’s pregame projection multiplied by game seconds remaining / 3600. They are labeled **Live est.**, clear when clocks, lineup or projections are incomplete, hide once final, and show a dash when stale. These are Blitz estimates, not MFL live forecasts. Starter inputs are registered by build 51; older subscriptions show no estimate until the phone updates. The actual scores remain MFL totals. Team records stay on the in-app scoreboard.

Build 52 also fixes the phone-to-server artwork handoff: the exact prepared content is retained before asynchronous publication and sent to both destinations. It never uses a just-read ActivityKit snapshot as the artwork receipt. Token arrival, delayed content observation and newer foreground scores preserve the prepared artwork. Artwork completed during another update is queued. Foreground adoption and failed artwork reads preserve the existing activity’s logos/colors. Re-registration also preserves server artwork and newer score/estimate state. Settings → Background scoring retains the latest 30 lifecycle events; the server keeps 64 sanitized lifecycle reasons/timestamps. These distinguish explicit app/server ends, expiry, token invalidation and observed SDK removal without claiming an underlying iOS reason.

The curl configuration layer must preserve UTF-8 (`ensure_ascii=False`); curl does not decode JSON Unicode escapes. A real loopback HTTP regression verifies the complete APNs body byte-for-byte, including punctuation and emoji. This was corrected September 13 after the owner saw `0u20130` on the Lock Screen.

Dates in `content-state` use default Swift Codable seconds since January 1, 2001. APNs envelope `timestamp`, `stale-date`, and `dismissal-date` use Unix seconds. Full APNs payloads fit 4 KB; long content drops thumbnails while keeping colors. Default ActivityKit static/dynamic size validation remains in the app.

## Privacy and access

Tailscale Serve exposes an independent private HTTPS port **8444**, proxying loopback **8792**. The existing historical test on 8443/8791 is preserved. Serve strips incoming identity headers and inserts the authenticated caller identity; the backend additionally checks an explicit owner-login allowlist. A device-generated 256-bit secret binds subscription mutations; only its hash is stored on the server. Browser-origin requests and redirects are rejected. This is a personal tailnet deployment, not public multi-user hosting.

The server stores the activity token, sandbox/production environment, week/league and two franchise IDs, abbreviations, participating starter names, small logo thumbnails/colors, starter IDs/pregame projections, live team estimates, last score state, and a scoring baseline in an owner-only SQLite database. It never receives the MFL password, session cookie, bids, trades or drafts. Upstream responses are reduced to the subscribed matchup; raw feeds are not retained. Logs omit requests, tokens, payloads and credentials. The separate APNs private key stays in an owner-only server file.

Disable/disconnect/dismissal cancels token observation and requests deletion. A Keychain queue retries uncertain/offline deletion on the next foreground connection or end. A deletion tombstone prevents an already-in-flight registration from recreating the subscription. Queue entries expire after eight hours; server tombstones contain only activity IDs and expiry and remain for another 7h50m after removal. When the app is suspended, a user dismissal may only be discovered through APNs invalidation or lease expiry. SQLite secure deletion clears removed subscription content; stopped services retain files until restarted/pruned or explicitly removed.

## Operations

- Deploy code/tests/unit: `scripts/deploy_live_activity.sh`. It preserves an existing config and APNs key, runs remote synthetic tests, then restarts only this service.
- Unit: `mfl-live-activity.service`; code: `~/.local/share/mfl-live-activity/`; config/key: `~/.config/mfl-live-activity/`; database: `~/.local/share/mfl-live-activity/state/subscriptions.sqlite3`.
- Inspect status through `/v1/status` with `X-Blitz-Sync: 1` from an allowed Tailscale device. Status contains readiness, subscription/accepted-push counts and a sanitized issue, never tokens.
- Stop: `systemctl --user stop mfl-live-activity.service`. Remove only this route: `tailscale serve --https=8444 off`. Never reset other Serve configuration.
- Server checks: `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s services/live_activity -p 'test_*.py' -v`.
- Native checks: `MatchupBackgroundSyncTests`, `MatchupActivityPresentationTests`, `MatchupActivityLayoutTests`. Tests use synthetic transport/activities; they do not start real Live Activities or send real Apple pushes.
